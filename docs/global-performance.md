# 全局性能架构优化

当前仓库已经从 Go 迁移至 Rust/Axum/Leptos。本次复用现有缓存管理器、SQLite、Tokio 和 Linux Page Cache，没有新增服务。

## 共性瓶颈与改动

| 共性路径 | 改动与收益 |
| --- | --- |
| 每本书一次 HTTP 写请求、一次 FULL 同步提交 | 书架可在创建时携带成员；添加、移除、收藏使用批量接口，每批最多 5000 项，一次原子事务。无效成员让整批回滚。 |
| 批量 SQL 逐本验证、逐本计算 MAX(position) | 使用 json_each、集合操作和排序窗口；固定由选中 ID 驱动点查，避免 SQLite 将 JSON 虚拟表放入错误的嵌套循环。已有成员保留位置，新成员按请求顺序追加。 |
| 堆叠列表 N+1、读取全部分类再补充信息 | 堆叠列表使用一个读取快照内的两次查询；普通分组入口先选分页分组，再补充进度、封面等信息。旧阅读进度转换使用有界并发。 |
| 各模块重复目录/搜索/集合查询及 JSON 序列化 | 统一缓存目录、搜索、内容库分页和集合响应；媒体、阅读器、预览及下载共用版本化文件元数据缓存。共享 Bytes/Arc，按键合并首次读取。 |
| 大媒体流在用户态重复缓存 64KiB 块 | 本地原文件大于 8MiB 时直接使用内核 Page Cache。远程提供者及小文件继续共享原有对齐块缓存。Range、ETag、流式传输保留。 |
| 导航清空筛选、列表和目录，全量刷新导致闪烁 | 模块各自持久化视图状态；用有界列表快照先显示内容，再请求校验；同目录刷新保留已渲染节点，过期响应按请求版本丢弃。 |

SQLite 迁移 016 增加集合成员的 file_id 索引，避免删除文件时外键级联扫描整个集合表，并为目录按更新时间/大小降序补充索引。连接保留 WAL、foreign_keys、busy_timeout 和 synchronous=FULL；不降低持久性。

## 缓存、预热和一致性

新增类别 files/metadata、files/directory、library/listing、library/collections、search/results 与已有 EPUB、封面、媒体、正文缓存共享同一个预算、压力回收和 LRU 策略。响应与元数据缓存有 120 秒 TTL；单响应最多 32MiB。失效由数据库写入版本决定，TTL 仅负责回收不再访问的旧版本。每个池连接在归还前检查 total_changes，所有通过应用连接进行的写入和触发器变更都会发布新版本，之后的请求不能命中旧版本。失败或回滚可以保守地失效，不会缓存错误响应。加载跨越新版本时不予缓存该结果。

每次外部缓存命中前重新验证会话，注销、过期和撤销立即生效；HTTP 仍返回 no-store。可通过 x-revaro-cache 的 miss、hit、coalesced 查看入口响应状态。系统状态 API 继续公开各类别内存、命中和淘汰数据。

启动后 10 秒预热小入口页，之后每 120 秒检查。目录/内容库只预读下一页，最多两个任务，不排无限后台队列；阅读入口只预热一本不超过 16MiB 的书，最多一个任务，并为交互解析保留余量。内存目标不足时跳过预热。没有嵌入封面的音频复用已有媒体探测的负结果，避免反复查找与解码。

8GiB 规划下缓存容量最多 5GiB，SQLite 页缓存合计 256MiB，mmap 窗口 512MiB。按主机和 cgroup 上限收缩；每 5 秒按 MemAvailable、进程 RSS 和 cgroup 当前占用调整目标，保留至少规划预算的 1/8。只保留实际使用过的派生数据，不为填满预算预分配内存。压力下释放缓存引用；被正在执行的请求持有的 Arc/Bytes 在请求结束后释放。实际 RSS 与缓存估算不同。

运行中绕过应用直接写 SQLite 不会触发进程内版本发布；数据库管理应沿用现有停服备份、恢复、迁移流程。

## 页面记忆

书籍、音乐、图片、视频分别保存搜索、收藏筛选、集合、排序和滚动位置；书籍还保存展开的堆叠。文件管理保存目录、搜索、排序和滚动；回收站、首页保存各自滚动位置。阅读器继续使用现有持久化阅读锚点；播放器继续使用现有持久化会话。

状态按账户名和模块隔离，存储失败不影响使用；显式 /f/{id}、/library/stacks/{id} 链接优先。删除的集合和堆叠在新响应校验后回退。导航前保存位置，渲染后恢复；必要时继续加载分页，内容缩短时限制到可达位置。浏览器列表快照每类最多 24 份，低内存设备 8MiB，其余 32MiB，不把整个文件列表写入同步 localStorage。

## 实测

2026-10-14，在当前机器上运行独立临时数据库、对象目录和真实 HTTP 服务。服务端为 debug 构建，浏览器 WASM 为 release；1 万条文件，重复读取 20 次，书架 200 本、堆叠 5000 本。原始数据位于 tests/performance/results。读数会受编译、浏览器及主机负载影响，不能作为生产延迟承诺。

| 操作 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 目录重复读取中位数 | 6.47ms | 0.92ms |
| 分组内容库重复读取中位数 | 71.86ms | 1.09ms |
| 文件搜索重复读取中位数 | 14.55ms | 1.09ms |
| 创建并填充 200 本书的书架，含读取校验 | 388.71ms | 48.53ms |
| 创建 5000 本书的堆叠 | 342.46ms | 148.24ms |
| 200 本书书架，每次调用额外等待 100ms | 21.55s | 0.245s |

100ms 场景在客户端每次调用前显式等待，用于模拟额外请求延迟，不是公网 RTT 测量。旧流程创建加逐本添加需要 201 次写调用，新流程只需一次写调用，最后都读取一次列表校验。改动后批量创建写入约 3.8ms；目录、分组内容库和搜索的冷读取分别约 7.8ms、45ms、12.6ms，未将缓存命中时间混作冷加载时间。

基准只填充分类与元数据行，没有测量首次 FFmpeg 解码或大型 EPUB 排版；这些功能由真实浏览器与阅读/媒体测试覆盖。长 FLAC 浏览器跳转测试因本机缺少用于生成大样本的 ffmpeg CLI 而跳过；原生 FLAC 探测/封面测试通过，CI 提供该样本生成工具。

复测命令：

```bash
cargo build -p revaro-server
python3 tests/performance/global_architecture.py --binary target/debug/revaro --batch --output /tmp/revaro-after.json
python3 tests/performance/global_architecture.py --binary target/debug/revaro --batch --latency-ms 100 --output /tmp/revaro-after-100ms.json
cargo test --workspace
node --test tests/transport/*.test.mjs
```

浏览器使用独立 18080 验证实例与 dist/performance-web。`cargo xtask check` 已通过，包括格式、工作区严格 Clippy、559 项 Rust 测试和 WASM 类型检查；另外 50 项传输测试通过。新增 global-state-memory.spec.ts 验证桌面 1280px、移动 390px 的集合、排序、目录、滚动恢复以及批量原子性、同目录刷新保留未变化 DOM 节点；现有测试覆盖取消陈旧请求、集合跨文档失效、书籍手势/排序、图库分页、媒体与阅读器、长 WAV Range 跳转、多断点菜单与工具栏。验证不会修改现有预览数据库。

前端针对 WASM 的 `clippy -D warnings` 尚有既存的 clone_on_copy、too_many_arguments 等 330 条问题；WASM release 构建和浏览器验证通过，后端 clippy -D warnings 通过。
